=========================================================
      নোটপ্যাড: নতুন প্রোজেক্ট সেটআপ গাইড (Backend)
=========================================================
ভবিষ্যতে যদি আপনি একদম শুরু থেকে এই প্রোজেক্টটি আবার তৈরি করতে চান, তবে নিচের ধাপগুলো সিরিয়াল অনুযায়ী অনুসরণ করবেন। প্রত্যেকটি কমান্ড এবং প্যাকেজের কাজ এখানে বাংলায় বুঝিয়ে দেওয়া হলো:

ধাপ ১: প্রোজেক্ট শুরু করা (Project Initialization)
---------------------------------------------------------
প্রথমে আপনার ফোল্ডারে টার্মিনাল ওপেন করে নিচের কমান্ডটি দিন:
> npm init -y

(এটি আপনার প্রোজেক্টে একটি package.json ফাইল তৈরি করবে, যা প্রোজেক্টের সব তথ্য এবং প্যাকেজগুলোর হিসেব রাখবে)

ধাপ ২: প্রয়োজনীয় প্যাকেজ (Dependencies) ইনস্টল করা
---------------------------------------------------------
আমাদের প্রোজেক্ট রান করার জন্য যেসব প্যাকেজ লাগবে, সেগুলো ইনস্টল করতে নিচের কমান্ডটি দিন:
> npm install express cors helmet morgan dotenv zod jsonwebtoken bcryptjs nodemailer @prisma/client

কোন প্যাকেজের কী কাজ?
- express: সার্ভার তৈরি এবং API বানানোর জন্য সবচেয়ে জনপ্রিয় ফ্রেমওয়ার্ক।
- cors: অন্য কোনো ওয়েবসাইট (যেমন- frontend) থেকে আমাদের API তে রিকোয়েস্ট করার পারমিশন দেওয়ার জন্য।
- helmet: আমাদের API-কে হ্যাকারদের থেকে সুরক্ষিত রাখতে কিছু সিকিউরিটি হেডার যুক্ত করে।
- morgan: টার্মিনালে API রিকোয়েস্টগুলোর লগ (Log) দেখার জন্য (যেমন- কে কোন লিংকে হিট করলো)।
- dotenv: ডাটাবেজ পাসওয়ার্ড বা গোপন কি (Key) গুলো .env ফাইলে লুকিয়ে রাখার জন্য।
- zod: ইউজার সঠিক ডাটা (নাম, ইমেইল, পাসওয়ার্ড) দিচ্ছে কিনা তা ভ্যালিডেশন করার জন্য।
- jsonwebtoken: লগিন করার পর ইউজারকে একটি টোকেন দেওয়ার জন্য, যাতে বারবার লগিন করতে না হয়।
- bcryptjs: ইউজারের পাসওয়ার্ডকে এনক্রিপ্ট (হাইড) করে ডাটাবেজে সেভ করার জন্য, যাতে হ্যাক হলেও পাসওয়ার্ড কেউ না বোঝে।
- nodemailer: ইউজারের ইমেইলে OTP বা ভেরিফিকেশন মেসেজ পাঠানোর জন্য।
- @prisma/client: ডাটাবেজের সাথে যোগাযোগ করার জন্য এটি Prisma এর মূল ক্লায়েন্ট।


ধাপ ৩: ডেভেলপার টুলস (Dev Dependencies) ইনস্টল করা
---------------------------------------------------------
নিচের প্যাকেজগুলো শুধুমাত্র কোড লেখার সময় আমাদের সাহায্য করবে (প্রোডাকশনে লাগবে না)। কমান্ড দিন:
> npm install -D typescript ts-node-dev prisma @types/express @types/node @types/cors @types/jsonwebtoken @types/bcryptjs @types/nodemailer @types/morgan

কোন প্যাকেজের কী কাজ?
- typescript: প্রোজেক্টে Typescript ব্যবহার করার জন্য।
- ts-node-dev: কোড সেভ করার সাথে সাথেই অটোমেটিকভাবে সার্ভার রিস্টার্ট করার জন্য (nodemon এর মত)।
- prisma: ডাটাবেজ টেবিল তৈরি এবং আপডেট করার টুল।
- @types/... : যেহেতু আমরা Typescript ব্যবহার করছি, তাই অন্যান্য প্যাকেজগুলোর টাইপ (Type) সাপোর্ট পাওয়ার জন্য এগুলো ইনস্টল করতে হয়।


ধাপ ৪: Typescript সেটআপ করা (tsconfig.json)
---------------------------------------------------------
টার্মিনালে নিচের কমান্ডটি রান করুন:
> npx tsc --init

(এটি একটি tsconfig.json ফাইল তৈরি করবে। ফাইলটি ওপেন করে আপনার প্রয়োজনমতো outDir, rootDir ইত্যাদি কনফিগার করে নেবেন)


ধাপ ৫: Prisma সেটআপ এবং ডাটাবেজ কানেক্ট করা
---------------------------------------------------------
১. Prisma শুরু করতে কমান্ড দিন:
> npx prisma init
(এটি prisma ফোল্ডার এবং একটি .env ফাইল তৈরি করবে)

২. এরপর .env ফাইলে আপনার ডাটাবেজের লিংক (DATABASE_URL) বসিয়ে দিন।

৩. prisma/schema.prisma ফাইলে আপনার টেবিল (Model) গুলো ডিজাইন করুন।

৪. ডাটাবেজে টেবিলগুলো পাঠাতে কমান্ড দিন:
> npx prisma db push
(এটি আপনার কোড অনুযায়ী আসল ডাটাবেজে টেবিল তৈরি করবে)

৫. ক্লায়েন্ট জেনারেট করতে কমান্ড দিন:
> npx prisma generate
(এটি Prisma Client কে আপডেট করে, যাতে আপনি কোডে টেবিলগুলোর নাম ঠিকমতো সাজেশন পান)


ধাপ ৬: package.json এ স্ক্রিপ্ট যুক্ত করা
---------------------------------------------------------
package.json ফাইলের "scripts" এর ভেতর নিচের লাইনটি যুক্ত করুন:
"dev": "ts-node-dev src/server.ts"

(এরপর থেকে সার্ভার চালু করতে টার্মিনালে শুধু "npm run dev" লিখলেই হবে!)


* অতিরিক্ত কমান্ড (Prisma এর জন্য) *
---------------------------------------------------------
- npx prisma migrate dev : আপনি যদি ডাটাবেজে নতুন কিছু যোগ করেন বা পরিবর্তন করেন, তবে এই কমান্ড দিয়ে মাইগ্রেশন হিস্ট্রি সেভ করতে পারবেন।
- npx prisma migrate reset : যদি কখনো ডাটাবেজ পুরোপুরি রিসেট বা ক্লিয়ার করার প্রয়োজন হয়।
- npx prisma studio : আপনার ডাটাবেজের ডাটাগুলো ব্রাউজারে সুন্দর একটি UI তে দেখার জন্য।


=========================================================
      ফাইল স্ট্রাকচার এবং কোড বোঝার সিকোয়েন্স (Flow)
=========================================================
একজন নতুন লার্নার হিসেবে প্রোজেক্টের কোন ফাইলের পর কোন ফাইল বুঝতে হবে এবং কাজ করতে হবে, তার একটি সহজ ফ্লো (Flow) নিচে দেওয়া হলো:

১. এন্ট্রি পয়েন্ট (Entry Point):
--------------------------------
-> src/server.ts
এই ফাইলটি দিয়ে আমাদের পুরো সার্ভার চালু হয়। এটি কোনো কাজ করে না, শুধু app.ts কে নিয়ে আসে এবং একটি পোর্টে (যেমন: 8000) সার্ভার রান করে।

২. অ্যাপ কনফিগারেশন (App Config):
--------------------------------
-> src/app.ts
সার্ভার চালু হওয়ার পর সব রিকোয়েস্ট প্রথমে এখানে আসে। এখানে আমরা সিকিউরিটি (cors, helmet) এবং অন্যান্য গ্লোবাল সেটিংস বলে দিই। এরপর রিকোয়েস্টটিকে মূল রাউটিং ফাইলের দিকে (main.ts) পাঠিয়ে দিই।

৩. মেইন রাউটার (Main Router):
--------------------------------
-> src/routes/main.ts
পুরো অ্যাপ্লিকেশনের ট্রাফিক পুলিশ হলো এই ফাইল। এখানে বলা থাকে কোন লিংকে (যেমন: /api/v1/auth) রিকোয়েস্ট আসলে কোন মডিউলে (Module) পাঠাতে হবে। এটি রিকোয়েস্টটিকে নির্দিষ্ট মডিউলের রাউটারের কাছে (যেমন: auth.routes.ts) পাঠিয়ে দেয়।

৪. মডিউল রাউটার (Module Router):
--------------------------------
-> src/modules/auth/auth.routes.ts
এই ফাইলটি শুধু Authentication এর রাউটগুলো ম্যানেজ করে। কেউ যদি /register এ রিকোয়েস্ট করে, তবে এটি সেই রিকোয়েস্টকে নির্দিষ্ট কন্ট্রোলারের (Controller) কাছে পাঠায়।

৫. কন্ট্রোলার (Controller):
--------------------------------
-> src/modules/auth/auth.controller.ts
কন্ট্রোলারের কাজ হলো ইউজারের রিকোয়েস্ট গ্রহণ করা এবং রেসপন্স (Response) দেওয়া। এখানে প্রথমে Zod (auth.validation.ts) দিয়ে চেক করা হয় ইউজারের ডাটা সঠিক আছে কিনা। ডাটা সঠিক থাকলে এটি Service (auth.service.ts) কে ডাটাগুলো দিয়ে বলে, "ডাটাবেজে সেভ করে আসো"। 

৬. সার্ভিস (Service):
--------------------------------
-> src/modules/auth/auth.service.ts
ডাটাবেজের সাথে আসল কাজগুলো এখানেই হয়! কন্ট্রোলার থেকে ডাটা পেয়ে এটি Prisma দিয়ে ডাটাবেজে ইউজার সেভ করে, ইমেইলে OTP পাঠায় (utils/email.ts এর মাধ্যমে) এবং কাজ শেষে রেজাল্ট কন্ট্রোলারের কাছে ফেরত পাঠায়। 

৭. ইউটিলিটি ফাইলস (Utility/Helper Files):
--------------------------------
-> src/utils/...
এই ফোল্ডারে এমন কিছু ফাইল থাকে যা পুরো প্রোজেক্টে বারবার কাজে লাগে। যেমন:
- email.ts (ইমেইল পাঠানোর ফাংশন)
- apiError.ts & apiResponse.ts (সুন্দরভাবে এরর এবং সাকসেস মেসেজ দেখানোর জন্য)
- asyncHandler.ts (try-catch বারবার না লিখে সহজে এরর হ্যান্ডেল করার জন্য)
- jwt.ts (ইউজার লগিন করলে টোকেন জেনারেট করার জন্য)

✅ সামারি:
ইউজারের রিকোয়েস্টের ফ্লো:
Request ➜ server.ts ➜ app.ts ➜ main.ts ➜ auth.routes.ts ➜ auth.controller.ts ➜ auth.service.ts ➜ Database!
